# 04. 註解色

## 換哪些字

- 只換 diff 畫面裡、註解中改動的字
    - 換：**註解範圍**與**改動的字**（見 [03-diff-ranges.md](03-diff-ranges.md)）的交集
        - 改了一部分的行：註解裡改動的那幾個字
        - 整段新增 / 刪除：整行註解
    - 不換
        - 程式碼裡改動的字
        - 沒改的註解
        - 平常的編輯器
- 參數組的註解色沒設 ⇒ 不換（用主題原本的）
- 改動的字不看框線的選項：整行、只改了空白的那幾段照樣算
    - 框線框不框只管框線，註解色照樣換

---

## 為什麼用 decoration

- VS Code 的註解色設定（`editor.tokenColorCustomizations`）是整個主題共用的
    - 寫在那裡，平常寫 code 時的註解也會跟著變
- ⇒ 用 decoration 的文字色蓋過主題的語法顏色，只上在 diff 的兩側
- 參數組的註解色不寫進任何設定

---

## 註解符號從哪來

- VS Code 沒有讓擴充讀語法 token 的 API，也沒有「某個語言的註解符號是什麼」的 API
- ⇒ 讀那個語言的 `language-configuration.json` 的 `comments`
    - 內建語言也是由內建擴充貢獻的，同一條路找得到
    - Better Comments 也是這樣讀
- 找法
    - 所有已安裝擴充的 `package.json` 裡 `contributes.languages`：語言 id → 語言設定檔
    - 同一個語言有多個擴充貢獻時，用先找到的那一個
    - 讀過的結果留著；擴充有增減時整份重找
- 讀法
    - 檔案是 JSONC：用 `jsonc-parser`，允許結尾逗號
    - 行註解：字串，或 `{ "comment": "//" }`（較新的寫法）
    - 區塊註解：兩個非空字串的陣列
    - 解析失敗、或行註解與區塊註解都沒有 ⇒ 這個語言不換
- 型別單一來源：`ICommentSyntax` 見 `src/commentSyntax.ts`

---

## 怎麼找註解

- 不是語法分析，是照註解符號找的近似
- 規則
    - 行註解：從符號到行尾
    - 區塊註解：可以跨行
        - 從檔頭掃到要找的最後一行，才知道某一行是不是在區塊註解裡面
    - 引號（`"`、`'`、`` ` ``）裡的註解符號不算（ex 字串裡的網址 `"https://…"`）
        - 只在**有行註解**的語言這樣做
            - 沒有行註解的多是標記語言（Markdown、HTML）：內文的撇號（`don't`）會被當成字串的開頭
        - 字串只看同一行
        - 字串裡的反斜線跳過下一個字元
- 只找「有改動的字」的那幾行；其餘的行只用來追蹤跨行的區塊註解

---

## 限制

- 跨行的字串（樣板字串）裡出現註解符號時，會被當成註解
- 沒有 `language-configuration.json`、或裡面沒有註解符號的語言不換
- 沒有行註解的語言不略過引號：引號裡的區塊註解符號也會被當成註解
