# 06. 設定的讀寫

## 讀：照 VS Code 的分層

- 參數組（`jctkDiffStyle.presets`、`jctkDiffStyle.activePreset`）照 VS Code 的分層讀
    - 專案設定（`.vscode/settings.json`）
    - 使用者設定
    - 內建的參數組
- 讀的是 VS Code 合併好的值；讀回來一律收斂（見 [05-presets.md](05-presets.md)）

---

## 寫：寫回參數組所在的那一層

- 參數組所在的那一層
    - 專案設定有 `jctkDiffStyle.presets`（空陣列也算有）⇒ 專案
    - 否則 ⇒ 使用者設定
- 寫到那一層的
    - 參數組清單與目前那一組（兩個鍵寫同一層）
    - 套用出來的底色與行號色
- 顏色為什麼跟著參數組寫同一層
    - 使用者設定是所有視窗共用的
    - 兩個視窗各用不同層的參數組時，顏色若都寫進使用者設定，後寫的會蓋掉另一個視窗的
- 結果
    - 專案設定放了參數組的專案：參數組與顏色都寫進那個 repo 的 `.vscode/settings.json`
        - 跟著版控：換電腦 clone 下來就有
        - 只套用到那個專案的視窗
    - 其他專案寫使用者設定，不會寫進別的 repo
- 讓一個專案的參數組跟著版控
    - 把 `jctkDiffStyle.presets`、`jctkDiffStyle.activePreset` 從使用者設定搬進那個專案的 `.vscode/settings.json`
    - Reload Window
- VS Code 寫設定用的是 `jsonc-parser` 的 `modify`
    - 用 prettier 管 `.vscode/settings.json` 的專案：寫出來的格式與 prettier 的輸出一致，面板調值不會讓格式檢查紅
        - 量過：同一套 `modify` 寫進一份 4 空白縮排、帶註解的 `settings.json`，結果與 prettier 的輸出逐字相同
    - 檔案裡的註解保留
- 型別與判定的單一來源：`SettingLayers`、`ResolvePresetLayer` 見 `src/settingLayers.ts`

---

## 套用出來的顏色：受管的鍵

- 寫在 `workbench.colorCustomizations` 的 `[目前主題]` 那一格
    - 參數組是照某個主題的底色調的
- 受管的鍵：單一來源 `DIFF_COLOR_KEYS`、`LINE_NUMBER_KEYS`、`MANAGED_COLOR_KEYS` 見 `src/colorSettings.ts`
    - 底色：VS Code 內建 diff 的整行、字、行號欄，新增與刪除各一套
    - 行號色：一般的行號、游標所在那一行的行號
- 寫入規則
    - 只動受管的鍵：同一個物件裡的其他鍵（ex 自己設的分頁顏色）原樣留著
    - 其他主題格子裡的受管鍵清掉：換主題時搬到新主題那一格
    - 清完變成空的主題格子整格拿掉
    - 不在任何主題格子裡的受管鍵不動：那是使用者自己設的、全主題通用的值
    - 參數組的行號色不換 ⇒ 拿掉行號的兩個鍵，回到主題原本的
    - 算出來的值與那一層現在的值相同 ⇒ 不寫
- 行號色：所有編輯器一起變
    - VS Code 沒有 diff 專用的行號色，decoration 也改不了行號
- 主題換了 ⇒ 重寫顏色、面板重畫

---

## 移除顏色

- 命令「移除寫進設定的顏色」
    - 使用者設定：拿掉所有主題格子裡的受管鍵
    - 專案設定：有 `workbench.colorCustomizations` 時一樣拿掉
- 擴充還裝著的話，下次切換或調整參數組、或重新載入視窗時會再寫回去
    - ⇒ 解除安裝前先跑這個命令；不跑的話，最後一次套用的顏色會留在設定裡

## 介面語言

- `jctkDiffStyle.language` 只在使用者設定（`package.json` 的 `scope: application`）
    - 不照參數組那一層寫：語言是個人的偏好，不該跟著專案的版控給別人
    - 選回「跟著 VS Code」時拿掉這個鍵
- 讀到認不得的值 ⇒ 當成跟著 VS Code
- 其餘規則見 [01-overview.md](01-overview.md)〈介面語言〉

---

## 被蓋掉的警告

- 比參數組那一層優先的設定，也在 `[目前主題]` 那一格設了受管的鍵 ⇒ 那幾項在這個專案調了看不到效果
    - 參數組在使用者設定：看專案設定與專案資料夾設定
    - 參數組在專案設定：看專案資料夾設定
    - 不在主題格子裡、或在別的主題格子裡的不算：蓋不掉限定主題的值
- 面板最上面列出被蓋掉的鍵
- 被蓋掉的鍵變了才重送面板：拖動中面板不會被重畫

---

## 自己寫設定的回音

- 擴充寫參數組時，自己也會收到設定變更事件
    - 把它當成別處改的而重讀，會蓋掉記憶體裡較新的狀態
- 判定：下面兩種都算回音，不重讀
    - 寫的期間收到的事件
        - 參數組是兩個鍵、分兩次寫：寫完第一個鍵時的事件裡，第二個鍵還是舊值，跟寫進去的那一份對不上
    - 設定裡現在的內容與最後一次寫進去的相同
- 別處改的（手改、另一個視窗、git pull）⇒ 重讀、套用、面板重畫
- 型別單一來源：`IEchoGuard` 見 `src/echoGuard.ts`

---

## 節流

- 三件事各自節流
    - 重畫框線：最頻繁，拖動時跟得上手
    - 寫顏色：拖動時看得到底色跟著變，又不每一格都寫檔
    - 存參數組：不影響畫面，只要最後存得到
    - 間隔是 `extension.ts` 裡的常數
- 行為
    - 第一次要求馬上跑
    - 跑的期間來的要求合併成「跑完再跑一次」，用的是那時最新的狀態
    - 兩次開跑之間至少隔一段時間
    - 同一時間只跑一個：兩次寫入不交錯，後寫的一定是新的值
    - 擲錯時記進診斷紀錄，不影響之後的要求
- 為什麼不是防抖（停下來才跑）：畫面要跟著手即時變
- 停用擴充時：還沒寫的顏色與參數組寫完
- 型別單一來源：`IThrottledTask` 見 `src/throttledTask.ts`
