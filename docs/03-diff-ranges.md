# 03. 框線與改動的字

## 兩種輸出

- 比對 diff 的兩側，每一側各算出兩樣東西
    - **框線範圍**：要畫框線的地方
    - **改動的字**：VS Code 在「字」那一層上底色的地方
        - 換註解色只從這裡面取（見 [04-comment-color.md](04-comment-color.md)）
- 範圍一律在同一行內，行與字元從 0 起算
- 型別單一來源：`IDiffRanges`、`ITextRange`、`IBorderRangeOptions` 見 `src/diffRanges.ts`

---

## 比對：跟 VS Code 用同一套

- 比對：`vscode-diff`，從 VS Code 原始碼抽出的同一套
- 照讀 VS Code 自己比對時用的設定
    - `diffEditor.diffAlgorithm`：`legacy` 用舊的演算法，其餘用 advanced
    - `diffEditor.ignoreTrimWhitespace`：打開時只差頭尾空白的行不算改動
    - `diffEditor.maxComputationTime`：沒設時用 VS Code 的預設值
- 不偵測搬移的程式碼
- 這些設定一改就重算

---

## 判定規則

- 每一段變動依「兩側各有沒有行」分兩種
    - 只有一側有行：**整段新增 / 刪除**，那一側的每一行（空行除外）是一段改動的字
    - 兩側都有行：VS Code 算出來的每一段改動的字（`innerChanges`）
        - 跨行的那一段切成每行一段
        - 長度 0 的段落丟掉
            - 跨行的範圍常收在下一行的第 1 欄（代表包含換行），切開後那一段長度是 0
        - 一段改動的字只算進「起點落在那一側變動行裡」的那一側
- 每一段改動的字一律算進**改動的字**
- 畫不畫**框線**，看那一段是不是下面兩種
    - **整行**：這一段以外，那一行只剩空白
        - 只在參數組的「整段新增 / 刪除也框」打開時框
    - **只改了空白**：這一段全是空白
        - 只在參數組的「只改了空白的也框」打開時框
    - 兩種都是（ex 新增一行只有空白的行）⇒ 兩個選項都打開才框
    - 兩種都不是 ⇒ 框

### 行為對照表

- 比對設定：`ignoreTrimWhitespace` 關掉

| 情況                                      | 例                                        | 框線（預設）          | 框線（對應選項打開）                 | 改動的字         |
| ----------------------------------------- | ----------------------------------------- | --------------------- | ------------------------------------ | ---------------- |
| 改了一部分的行                            | `OverflowButton` → `AppOverflowButton`    | 框 `App`              | 框 `App`                             | `App`            |
| 整段新增 / 刪除                           | 新增一個函式                              | 不框                  | 「整段也框」：整行框                 | 整行             |
| 一行改了幾個字，後面接著新增一整段        | `"default"` → `"default",` 之後新增一整段 | 只框 `,`              | 「整段也框」：新增的行整行框         | `,` 與新增的整行 |
| 縮排沒變、字全換了                        | `    foo` → `    bar`                     | 不框                  | 「整段也框」：框 `bar`               | `bar`            |
| 外面包了一層，裡面多一層縮排              | `<div>` 外面包 `<AppRoot>`                | 只多了縮排的行不框    | 「只改了空白的也框」：框多出來的縮排 | 縮排也算         |
| 行尾多了空白                              | `a();` → `a();  `                         | 不框                  | 「只改了空白的也框」：框行尾的空白   | 行尾的空白       |
| 空白與字在同一段                          | `x();` → `    const value = x();`         | 框 `   const value =` | 同左                                 | 同左             |
| 只差頭尾空白、`ignoreTrimWhitespace` 打開 | `call();` → `    call();`                 | 不是改動，不框        | 不是改動，不框                       | 不是改動         |

## 為什麼這樣判

- 框線的用途：指出一行裡是哪幾個字改了
    - 整行都換了：框線不帶新資訊，VS Code 已經整行上色
- 「整行」看的是「這一段以外只剩空白」，不是「從行首到行尾」
    - VS Code 對齊時常把開頭的縮排算成沒變
    - ex 外面包一層 `try` 時新加的 `    } finally {`：改動的字是 `} finally {`，不含開頭的縮排
- 「一行改了幾個字，後面接著新增一整段」也照整段新增處理
    - VS Code 把那一行與後面新增的行算成同一段變動，新增的行整行都是改動的字
    - 不這樣處理的話，整段都會被框，「整段新增 / 刪除也框」關掉也沒用
- 只改了空白的預設不框
    - 外面包了一層時，裡面每一行都多一層縮排：框起來全是雜訊
    - 要看空白的改動（Python、YAML 的縮排）時打開
- VS Code 自己畫的底色，擴充拿不掉
    - 要連底色一起不顯示：VS Code 的 `diffEditor.ignoreTrimWhitespace`
        - diff 分頁標題列有一顆按鈕切換它（命令 `toggle.diff.ignoreTrimWhitespace`）
        - 代價：所有頭尾空白的改動都看不到

## 找到 diff 分頁的兩側

- 每個分頁群組目前的分頁是一般的 diff（`TabInputTextDiff`）才處理
- 兩側：看得到的編輯器裡，文件對得上、欄號是空的或等於那個群組的那一欄
    - diff 的兩側在擴充眼中**沒有欄號**
        - VS Code 以「分頁的控制項 === 這個編輯器」找它在哪一欄
        - diff 分頁的控制項是整個 diff 元件，不是裡面那兩個編輯器（`mainThreadEditor.ts` 的 `matches`）
        - ⇒ 只認同一欄的話一條框線都不畫，而且沒有任何錯誤
    - 欄號等於群組那一欄的也收：VS Code 哪天替 diff 的兩側補上欄號時照樣找得到
    - 同一個檔案在別欄以一般分頁開著：那個編輯器有自己的欄，不會被挑進來、不會被框
- 單欄（inline）：原本那一側不是編輯器
    - 文件從已開的文件找，找不到就向 VS Code 要
    - 只畫新增那一側
- 兩側都找不到：診斷紀錄寫出看得到的編輯器與它們的欄號
- 不在任何 diff 裡的編輯器：清掉本擴充的 decoration
- 重畫的時機
    - 看得到的編輯器變了
    - 分頁或分頁群組變了
    - 看得到的文件內容變了
    - 參數組換了或值變了
    - `diffEditor` 開頭的設定變了

---

## 框線的樣式

- 每一側一個 decoration
    - 框線：`<粗細>px <樣式> <那一側的框線色>`
    - 圓角
    - 在範圍邊緣打字時範圍不延伸（`ClosedClosed`）
- 「畫框線」關掉：不建立框線的 decoration
- 參數組換了或值變了：decoration 整組重建

---

## 限制

- `vscode-diff` 跟的 VS Code 版本比較舊：少數情況下框線與 VS Code 上色的範圍會對不齊
- 不偵測搬移的程式碼：搬移的那一段照新增 / 刪除算
- 多檔 diff、merge editor 不畫框線
- 單欄時刪除的那幾行不畫：那是 VS Code 插進來的顯示區塊
    - 編輯器太窄時 VS Code 會自己把 diff 切成單欄（`diffEditor.useInlineViewWhenSpaceIsLimited` 預設開）
        - 使用者看到的是「刪除那一側的框不見了」
        - 關掉那個設定就一直並排：README〈已知限制〉寫給使用者
